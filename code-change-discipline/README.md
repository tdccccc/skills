# Code Change Discipline

让 Agent 改代码时先选测试策略，再动手实现。无论是一行小修、功能开发、Bug 修复、重构还是优化，都要求用实际验证结果说明改动是否可靠。

## 它会做什么

- **功能和 Bug**：先写测试并确认失败，再做最小实现直到通过，最后跑相关回归。
- **纯重构和优化**：先确认现有行为或性能基线，全程保持结果正确，不会硬造失败测试。
- **无法先测的情况**：说明原因，改用可行的验证方式，并交代是否需要补测试。
- **保护现有工作**：保留无关的未提交修改，只处理本次任务。

源码、测试以及会改变运行结果的配置都适用。纯文档、注释和格式化只做必要检查。

## 怎么用

安装后通常会在代码改动任务中自动启用，直接描述需求即可：

```text
修复空端口被解析成 0 的问题
给订单服务增加取消订单功能
重构发票计算，保持行为不变
```

随本仓库安装：

```bash
curl -fsSL https://raw.githubusercontent.com/tdccccc/skills/main/bootstrap.sh | bash
```

## 与 Helm 的关系

小改动直接使用本 skill。多步骤工作使用 Helm 时，Helm 会继续遵守这套纪律，并额外管理 phase、Checkpoint 和提交节点。

具体执行规则见 `SKILL.md`。
